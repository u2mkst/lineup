# 축구방

11인제 축구 **라인업 짜기**와 **전술 애니메이션 짜기**를 한 곳에서 하는 웹앱.

**우리 팀 전용 구단 운영 앱**. 일정과 참석 투표, 경기 기록과 시즌 통계, 선수단, 게시판, 그리고 라인업·전술 애니메이션 보드를 한곳에서 씁니다.
팀원만 쓸 수 있어요. **선수는 감독에게 받은 개인 코드**를 입력하고 아이디·비밀번호만 정하면 그 선수로 가입돼요(이메일 불필요, 한 번 로그인하면 자동 로그인 유지). 감독·스태프는 이메일로 가입한 뒤 합류코드로 들어와요. 역할은 관리자 / 선수 두 가지예요.

## 화면

| 탭 | 내용 |
|---|---|
| 홈 | 대시보드: 시즌 요약(경기·승률·득점·실점, 최근 5경기 폼), 다음 일정(바로 투표), 경기 결과(스코어·득점자), 득점 기록(득점/도움/공격포인트 TOP5), 인스타그램·유튜브(@yeonmufc) 바로가기, 공지 |
| 일정 | 월간 달력(매치·회식·연습·기타), 참석 투표와 마감, 참석률·투표율, 라인업과 댓글 |
| 기록 | 시즌별 팀 기록(경기당 득점·실점, 무실점, 다득점 쿼터…)과 개인 기록(득점왕, 도움왕, 최고수비수, POTM, 최다 출전…), 경기 목록 |
| 전술 | 팀 공유 전술 보기·"확인했어요"·댓글, 내 전술 편집 |
| 더보기 | 선수단(구성·평균 연령·시즌 기록), 게시판(공지 고정·댓글), 내 프로필, 구단 관리 |

- **관리자**: 일정 등록, 경기 기록 입력(쿼터별 점수·골·도움·POTM), 선수 관리(번호 교체·겸임 포지션·부상·출생연도), 합류코드 재발급, 팀원 권한·선수 연결·내보내기, 전술 서버 저장과 팀 공유
- **선수**: 참석 투표, 전술·기록 조회, 게시판, 팀 공유 전술 복사(내 기기에만 저장)

## 선수 개인 코드로 가입

1. 관리자 페이지 → **선수 코드**에서 선수마다 8자리 코드(선수를 추가하면 자동 생성)를 확인하고 "보내기"로 **그 선수에게만** 전달 (링크 `/#/code/코드`를 열면 코드가 채워져요)
2. 선수는 "선수 코드로 시작하기" → 코드 입력 → "○○ 선수가 맞나요?" 확인 → 아이디(영문 소문자·숫자·_ 3~20자) → 비밀번호(6자 이상) → 바로 로그인
3. 코드는 한 번만 쓸 수 있고, 가입한 선수는 그 선수 프로필에 자동 연결돼요. 이후엔 아이디로 로그인하거나 이 기기에 세션이 유지돼요
4. 비밀번호를 잊으면 관리자가 "비밀번호 재설정 코드"를 발급 → 같은 화면에서 새 비밀번호만 정해요

로그인 이메일은 내부적으로 `아이디@lineup-jade-xi.vercel.app`으로 만들어지고(메일은 발송되지 않아요), 가입은 Edge Function `claim-player`(`supabase/functions/claim-player`)가 service role로 처리해요. 배포: `supabase functions deploy claim-player --no-verify-jwt`. 코드 테이블 `player_codes`는 관리자만 읽을 수 있어요. 아이디 도메인은 `logic.ts`와 `src/lib/playerId.ts`의 `ID_DOMAIN`을 같게 유지해야 해요.

## 처음 쓰는 사람도 쉽게

한 화면에 질문 하나, 큰 버튼 하나, 위쪽에 진행 막대(토스식 단계 화면)로 안내해요.

- **관리자 첫 설정**: 구단 이름 → 선수 한 명씩(이름 → 번호 → 포지션, 번호 중복은 바로 알려줘요) → 첫 일정 → 팀원 초대 링크 → 홈 화면 설치. 구단 관리의 "마법사 열기"로 다시 열 수 있어요
- **팀원 합류**: 초대 링크 → 이메일·비밀번호(조건을 입력하며 확인) → 자동 합류 → "나는 누구인가요?"
- 초대·설정 링크의 코드는 이 기기에 기억돼서, 인증 메일을 확인하고 돌아와도 이어져요

## 공개 페이지 (`/info`)

로그인 없이 누구나 볼 수 있는 페이지예요(팀 이름·엠블럼, 올해 전적, 최근 경기 결과, 다가오는 경기, 인스타·유튜브 링크). 공개해도 되는 값만 골라 돌려주는 DB 함수 `public_overview()`가 만들어 주고, 테이블 자체는 계속 닫혀 있어요. **선수 이름·기록, 참석, 전술, 팀원, 게시판, 능력치, 일정 메모, 회식·연습 일정은 절대 나오지 않아요.** 관리자 페이지 → 구단 설정 → 공개 페이지에서 켜고 끌 수 있어요.

## 관리자 페이지 (`/admin`)

앱과 완전히 분리된 관리자 전용 화면이에요(자체 사이드바 레이아웃, 폰에서는 상단 메뉴). 관리자가 아니면 "관리자만 들어올 수 있어요", 로그인 전이면 로그인 화면만 보여요. 접근 제어는 화면이 아니라 서버(RLS)가 맡아요.

| 메뉴 | 내용 |
|---|---|
| 개요 | 팀원·선수·예정 일정·능력치 평가 현황, **할 일**(기록 미입력 경기, 다음 일정에 투표 안 한 선수, 프로필 미연결 팀원, 미평가 선수), 합류코드 |
| 팀원·권한 | 관리자 지정/해제, 선수 프로필 연결, 내보내기 |
| 선수 관리 | 추가(한 명씩/붙여넣기), 번호·포지션·부상·출생연도, 번호 교체, 삭제 |
| 능력치 (비공개) | 감독 평가 입력 — 빠른 선발에 쓰여요 |
| 일정·기록 | 일정 등록·수정·삭제, 경기 결과·득점·도움·POTM 입력, 상태별 보기 |
| 구단 설정 | 구단 이름, 합류코드 재발급, 설정 마법사, 공식 채널, 로그아웃 |

`vercel.json`의 rewrite로 `/admin`이 같은 앱으로 열려요. 예전 `#/admin` 주소는 `/admin`으로 이동해요.

## 감독 도구 (관리자 전용)

- **선수 추가**: 선수단 화면 오른쪽 위 "＋ 선수 추가" — 한 명씩(번호는 비어 있는 번호를 추천) 또는 "여러 명 한꺼번에"(한 줄에 `7 김철수 MF` 형태로 붙여넣기, 순서·포지션 한글 표기 자유)
- **🔒 능력치 평가**: 선수마다 슈팅·패스·드리블·수비·스피드·체력·피지컬(골키퍼는 골키핑) 1~10점과 메모. `player_ratings` 테이블에 따로 저장되고 RLS로 관리자만 읽고 쓸 수 있어요. 선수 화면·전술·공유 링크에는 절대 들어가지 않고, 브라우저 저장소에도 남기지 않아요
- **⚡ 빠른 선발**: 일정 상세 메뉴 또는 전술 편집의 라인업 패널에서. 포메이션 각 자리(윙·센터백·공격수 등)에 맞는 능력치 가중치와 포지션 적합도로 최적의 11명을 배치해요. 대상은 전체 선수 / 참석자만 / 참석+미정, 부상자는 자동 제외, 마음에 안 드는 선수는 ✕로 빼고 다시 계산

## 전술 보드
- 포메이션, 선수 배정, 상대팀(선택), 장면(키프레임) 애니메이션, 곡선 이동 경로, 달리기·패스 화살표·구역
- 선택 도구(그룹 이동), 장면별 교체, 선수별 이동 타이밍, 공 소유, 세트피스 템플릿 6종
- 내보내기: PNG, GIF, 영상, 이미지 템플릿 3종, 카카오톡 공유(`VITE_KAKAO_JS_KEY`가 있을 때 카드)
- PWA: 홈 화면 설치, 오프라인 동작

서버 환경변수가 없으면 로그인 없이 이 기기에서만 쓰는 개인 전술 보드로 동작해요.

## Supabase 설정

1. 새 프로젝트에서 `supabase/migrations/*.sql`을 파일명 순서대로 SQL Editor로 실행 (테이블, RLS 정책, 기본 명단, 일정·기록, 구단·멤버)
2. `.env.local`에 `.env.example`처럼 URL과 publishable key 입력 (Vercel에는 같은 이름의 환경변수)
3. 첫 관리자: 마이그레이션이 만든 1회용 `team_secret.admin_code`로 설정 링크 `https://<사이트>/#/setup/<admin_code>`를 만들어 한 번 열기 → 이메일로 가입하면 코드 입력 없이 관리자가 되고 설정 마법사가 시작돼요. 관리자가 생기면 이 코드(링크)는 사라져요
4. 팀원 초대: 마법사 마지막 단계(또는 구단 관리)에서 초대 링크 `https://<사이트>/#/join/<합류코드>`를 단체방에 공유 — 누르고 가입하면 자동 합류 (재발급하면 이전 코드는 무효). 링크가 안 열리면 합류코드를 직접 입력할 수도 있어요
5. **이메일 인증(Confirm email)**: Supabase 대시보드 → Authentication → Sign In / Providers → Email 에서 "Confirm email"을 켜면 가입 시 인증 메일이 가요. 같은 메뉴의 URL Configuration에서 **Site URL**을 배포 주소로 바꾸고 Redirect URLs에도 추가해야 인증 링크가 올바르게 돌아와요. 기본 제공 메일은 시간당 발송 수가 아주 적어서, 팀원이 많다면 Project Settings → Authentication → SMTP에서 자체 SMTP를 연결하세요

카카오톡 카드는 Kakao Developers에서 앱을 만들고 JavaScript 키를 `VITE_KAKAO_JS_KEY`로 넣은 뒤, 앱 설정 > 플랫폼 > Web에 사이트 주소를 등록해야 해요.

접근 제어는 전부 RLS가 맡아요. 모든 테이블은 멤버만 읽을 수 있고, 쓰기는 관리자(또는 본인 투표)만 가능해요. 브라우저에 들어가는 키는 publishable key뿐이에요.

React + Vite + TypeScript + zustand + supabase-js. 배포는 Vercel (Framework: Vite, 빌드 `npm run build`, 출력 `dist`).
